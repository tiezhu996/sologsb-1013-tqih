# 舞台演出串联与提示表编辑器

导演和舞台监督使用的纯前端提示表工作台。可按幕、场和提示点维护演出流程，拖动后自动顺延后续时间，并持续检查负责人、时间、道具、演员和引用关系。

## 功能

- 按幕、场维护开场时间、灯光、音响、道具、演员、负责人和工作备注。
- 提示点原生拖拽排序；调整后自动重算当前场后续提示时间。
- **每次保存形成变更单**：记录场次、提示与字段的新旧值。未触碰同一字段的改动直接并入正式表；两边都改过同一字段的转入「待裁决区」，由场务逐条采纳或驳回后才写入正式表。
- **锁定场次保护**：场次锁定后，收到的任何外部改动（以及锁定状态下保存的改动）都先停留在待裁决区，不会覆盖正式表。
- **接收外部变更单**：可粘贴他人导出的变更单 JSON，或在同浏览器多标签页间自动接收；合并规则与本地保存一致。
- 工作副本独立于正式表：编辑期间他人改动到达时，未碰字段自动跟进，自己已改字段保留待裁决；可随时放弃未保存改动。
- **旧版提示表载入**：启动时按原顺序载入旧版本地数据；字段损坏的提示整条进入「异常箱」（记录损坏字段与原位置），其余场次照常编辑，异常记录可按默认值修复归位。
- 检查负责人空缺、同场时间冲突、跨场道具撞场、演员撞场及已删除提示的失效引用。
- 复制上一场完整流程，并自动生成独立提示 ID（提交时作为新增场次/提示进入变更单）。
- 锁定场次或保存锁定版本，从历史版本建立可编辑修订。
- 选择锁定版本后按提示逐条比较负责人、时长和流程差异。
- 文档级撤销/重做、键盘顺序调整、搜索和浏览器本地持久化。
- 可交互的首演示例数据覆盖两个场次、多类提示和待处理问题。

## 技术栈

- Ember 5
- TypeScript
- Ember Paper
- Glimmer 组件
- 原生 `localStorage`

## 本地开发

```bash
npm install
npm start
```

浏览器打开终端输出的开发地址。

## 生产构建

```bash
npm run build
```

生产文件位于 `dist/`。

## 键盘操作

| 快捷键 | 操作 |
| --- | --- |
| `Alt + ↑ / ↓` | 将当前提示前移或后移 |
| `N` | 新建提示（表单编辑区域外） |
| `Ctrl/Cmd + Z` | 撤销 |
| `Ctrl/Cmd + Shift + Z` 或 `Ctrl/Cmd + Y` | 重做 |

## Docker

容器内由 nginx 监听端口 `80`，源码不硬编码宿主端口。

```bash
docker build -t stage-cue-prompt-editor .
docker run --rm -p 10013:80 stage-cue-prompt-editor
```

宿主端口 `10013` 仅作为本地运行示例，实际端口由根编排文件统一管理。
